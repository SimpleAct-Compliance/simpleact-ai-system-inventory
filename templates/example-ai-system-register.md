# Beispielregister

Sechs Einträge, verkürzt auf die Felder, an denen sich etwas entscheidet. Erfundene Beispiele, aber die Konstellationen sind die, die in echten Registern vorkommen — einschließlich der unangenehmen.

---

## 1 Supportanfragen vorsortieren

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Fasst eingehende Supportanfragen zusammen und schlägt eine Kategorie vor |
| Werkzeug | Helpdesk-Software, KI-Funktion des Anbieters |
| Gefunden über | Release-Notes des Anbieters |
| Modell und Version | Anbieter nennt kein Modell; angefragt 12.9.2026, Antwort offen |
| Daten | Name, E-Mail, Vertragsnummer, **Freitext der Anfrage** |
| Besondere Kategorien | möglich über Freitext (Gesundheitsangaben in Reklamationen) |
| Was die Ausgabe auslöst | Kategorie wird übernommen, wenn niemand widerspricht |
| Geänderte Ausgaben im letzten Monat | 4 von etwa 1.100 |
| Acht Bereiche berührt | nein |
| Rechtliche Klasse | minimal; Art. 50 geprüft: keine Kennzeichnungspflicht, da kein Direktkontakt |
| Interne Einschätzung | mittel — Freitext kann Gesundheitsdaten enthalten |
| Offener Punkt | Modellversion beschaffen; Verantwortlich: Herr Weber; Termin: 31.10.2026 |

**Was dieser Eintrag zeigt:** Die Zahl 4 von 1.100 ist die eigentliche Aussage. Formal gibt es eine Aufsicht, praktisch wird sie nicht ausgeübt. Das ist kein Rechtsverstoß bei minimalem Risiko — es wäre aber einer, wenn die Klasse anders ausfiele.

---

## 2 Bewerbungen zusammenfassen

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Fasst Bewerbungsunterlagen zusammen und hebt Qualifikationen hervor |
| Werkzeug | allgemeines Sprachmodell über Schnittstelle |
| Gefunden über | Auslagenerstattung (Einzelabo der Personalleitung) |
| Betroffenenkreis | Bewerberinnen und Bewerber |
| Was die Ausgabe auslöst | Grundlage für die Vorauswahl zum Gespräch |
| **Acht Bereiche berührt** | **ja — Beschäftigung** |
| Eigene Rolle | **ungeklärt**: möglicherweise Anbieter nach Art. 25 Abs. 1 Buchst. d |
| Rechtliche Klasse | nicht bewertet |
| Offener Punkt | Rechtliche Bewertung Art. 25 und Anhang III Nr. 4; Verantwortlich: Frau Sandner (Recht); Termin: 10.10.2026; **bis dahin ausgesetzt** |

**Was dieser Eintrag zeigt:** Den Fall, für den das ganze Register da ist. Ein Einzelabo, über die Auslagenerstattung gefunden, kein Projekt, keine Beschaffung — und möglicherweise ein Hochrisikosystem, dessen Anbieter die eigene Organisation ist. „Nicht bewertet" mit Termin und ausgesetztem Betrieb ist hier das richtige Ergebnis, nicht eine schnelle Klasse.

## 3 Chatbot auf der Website

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Beantwortet Fragen von Website-Besuchern zu Produkten und Preisen |
| Gefunden über | bekannt, Projekt 2025 |
| Betroffenenkreis | Website-Besucher |
| Acht Bereiche berührt | nein |
| Rechtliche Klasse | minimal, **aber Art. 50 Abs. 1 greift** |
| Umsetzung Art. 50 | Hinweis „Sie sprechen mit einem KI-Assistenten" über dem Eingabefeld, sichtbar vor der ersten Eingabe; Nachweis: Screenshot vom 2.9.2026, Produktversion 3.4 |
| Interne Einschätzung | niedrig |

**Was dieser Eintrag zeigt:** Transparenz ist keine niedrigere Stufe, sondern eine zusätzliche Ebene — und sie gilt **seit 2.8.2026**. Der Nachweis nennt Datum **und** Produktversion; ohne die Version belegt der Screenshot nur, dass es einmal so aussah.

## 4 Zahlungsausfälle prognostizieren

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Schätzt je Neukunde die Wahrscheinlichkeit eines Zahlungsausfalls |
| Gefunden über | Beschaffung |
| Betroffenenkreis | gewerbliche und private Neukunden |
| Was die Ausgabe auslöst | bestimmt, ob Vorkasse verlangt wird |
| **Acht Bereiche berührt** | **ja — Kreditwürdigkeit** |
| Wird profiliert | **ja** |
| Art. 6 Abs. 3 | greift nicht, da Profiling natürlicher Personen |
| Rechtliche Klasse | Hochrisiko nach Anhang III Nr. 5 Buchst. b, soweit natürliche Personen betroffen |
| Eigene Rolle | Betreiber; Art. 25 geprüft 20.9.2026, Ergebnis: kein Rollenwechsel |
| Interne Einschätzung | hoch |

**Was dieser Eintrag zeigt:** Die Profiling-Rückausnahme. Die Tätigkeit sieht nach einer engen Verfahrensaufgabe aus, aber sobald natürliche Personen profiliert werden, trägt Art. 6 Abs. 3 nicht — unabhängig von allem anderen.

## 5 Übersetzung interner Dokumente

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Übersetzt interne Richtlinien ins Englische |
| Gefunden über | aggregierte Netzprotokolle |
| Daten | keine personenbezogenen Daten; Dokumente sind unternehmensintern |
| Eingaben zum Training genutzt | **unbekannt**; kostenloser Zugang, Bedingungen äußern sich nicht |
| Acht Bereiche berührt | nein |
| Rechtliche Klasse | minimal |
| Interne Einschätzung | mittel — Vertraulichkeit, nicht Datenschutz |
| Offener Punkt | Geschäftstarif mit vertraglicher Zusage prüfen; Verantwortlich: Herr Ohlsen (IT); Termin: 15.11.2026 |

**Was dieser Eintrag zeigt:** Ein rechtlich folgenloser Fall mit einem echten Risiko — interne Richtlinien gehen an einen Dienst, der sie möglicherweise zum Training verwendet. Genau deshalb sind die beiden Risikofelder getrennt. Und: Der kostenlose Tarif ist der Grund für die Lücke, nicht der Anbieter.

## 6 Verkaufsprognose

| Feld | Eintrag |
|---|---|
| Einsatzzweck | Schätzt den Absatz je Artikel für die Bestellplanung |
| Gefunden über | Beschaffung |
| Wie die Ausgabe entsteht | Regression auf eigenen Verkaufsdaten, Gewichte aus den Daten gelernt |
| **KI-System nach Art. 3 Nr. 1** | **ja** — Begründung: Ableitung aus Daten, nicht festgelegte Formel |
| Daten | keine personenbezogenen Daten |
| Acht Bereiche berührt | nein |
| Rechtliche Klasse | minimal |
| Interne Einschätzung | niedrig |

**Was dieser Eintrag zeigt:** Ein Fall, in dem die Begründung wichtiger ist als das Ergebnis. „Ja, aber minimal" mit einem Satz Begründung ist ein Nachweis. Dasselbe System ohne Eintrag wäre eine Lücke — und die Versuchung, es als „nur Statistik" nicht aufzunehmen, ist groß.

## Was an diesen sechs auffällt

| Eintrag | Gefunden über | Hätte eine Umfrage ihn gefunden? |

| 3 Chatbot | bekannt | ja |
