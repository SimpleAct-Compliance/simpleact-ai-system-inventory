# Was einen Eintrag braucht

Die Frage „ist das ein KI-System?" ist für das Inventar weniger wichtig, als sie klingt. Die praktisch wichtigere Frage ist: **Braucht es einen Eintrag?** Die Antwort ist häufiger Ja.

## KI-System (Art. 3 Nr. 1)

Ein maschinengestütztes System, das mit einem Maß an Autonomie betrieben wird, nach dem Einsatz anpassungsfähig sein kann und aus Eingaben ableitet, wie Ausgaben zu erzeugen sind — Vorhersagen, Inhalte, Empfehlungen oder Entscheidungen.

### Wo die Grenze liegt

| Fall | KI-System? |
|---|---|
| Formel in einer Tabelle | nein |
| Punktesystem mit Gewichten, die ein Mensch eingetragen hat | meist nein |
| Regelwerk mit hundert handgeschriebenen Wenn-Dann-Regeln | meist nein, aber begründen |
| Modell, das Gewichte aus Daten gelernt hat | ja |
| Sprachmodell über eine Schnittstelle | ja |
| Statistische Vorhersage aus Verkaufsdaten | kommt darauf an, wie sie entstanden ist |

Die unteren drei Zeilen sind einfach. Die oberen drei brauchen eine **Begründung im Eintrag** — auch wenn sie auf „kein KI-System" lautet. In einer Prüfung ist eine dokumentierte Negativbewertung ein Nachweis; ein fehlender Eintrag ist eine Lücke.

### Warum im Zweifel aufnehmen

Ein Eintrag für ein Werkzeug, das sich als Nicht-KI erweist, kostet zwanzig Minuten. Ein fehlender Eintrag für ein Werkzeug, das doch eines war, kostet die Aussage, dass das Inventar vollständig ist. Deshalb: aufnehmen, bewerten, Ergebnis festhalten — auch wenn es „fällt nicht darunter" lautet.

## Einsatzzweck

Kein Begriff der Verordnung, aber die Einheit, in der dieses Register arbeitet: **was ein System in einem bestimmten Zusammenhang für wen tut.**

Ein Sprachmodell ist kein Einsatzzweck. „Kundenanfragen im Support vorsortieren" ist einer. „Bewerbungen im Personalbereich zusammenfassen" ist ein zweiter, und er ist rechtlich ein anderer Fall — selbst wenn beide dasselbe Modell über dieselbe Schnittstelle nutzen.

## Zweckbestimmung (Art. 3 Nr. 12)

Die Verwendung, für die ein System **vom Anbieter** vorgesehen ist, einschließlich des Nutzungskontexts.

Im Inventar gehören beide Angaben getrennt: die Zweckbestimmung des Anbieters und der eigene Einsatzzweck. Weichen sie voneinander ab, ist das der Hinweis auf einen möglichen Rollenwechsel — siehe [scope-and-actors.md](./scope-and-actors.md).

## Eingebettete KI

Kein Rechtsbegriff, aber die Kategorie, die das Inventar am häufigsten verfehlt: eine KI-Funktion in einer Software, die aus anderen Gründen gekauft wurde.

Sie ist unangenehm, weil es **keinen Anlass** gibt, sie zu bemerken. Niemand beschafft sie, niemand beantragt sie, es gibt kein Projekt. Sie erscheint in einem Release und ist am nächsten Tag in Benutzung. Deshalb braucht das Inventar eine eigene Suche dafür und nicht nur ein Feld.

## Schatten-KI

Nutzung ohne Kenntnis der Organisation. Der Begriff klingt nach Regelverstoß, beschreibt aber meist etwas anderes: Jemand hatte eine Aufgabe, ein Werkzeug half, und es gab keinen erkennbaren Weg, das anzumelden.

Das ist für das Inventar eine nützliche Lesart, weil sie zur richtigen Maßnahme führt. Ein Verbot verlagert die Nutzung auf private Geräte, wo sie unsichtbar wird. Ein Aufnahmeweg mit acht Feldern wird benutzt.

## Status eines Eintrags

| Status | Bedeutung |
|---|---|
| geplant | noch nicht in Benutzung |
| Pilot | **in Benutzung** — siehe unten |
| in Betrieb | in Benutzung |
| abgeschaltet | nicht mehr in Benutzung, Eintrag bleibt |

„Pilot" ist kein Schutzraum. Wenn Beschäftigte ein System im Alltag benutzen, ist es in Betrieb genommen — auch wenn das Projekt so heißt und kein Budget hat. Die Forschungsausnahme der Verordnung greift hier nicht.

Abgeschaltete Systeme bleiben im Register. In einer Prüfung wird gefragt, was zu einem bestimmten Zeitpunkt lief.
